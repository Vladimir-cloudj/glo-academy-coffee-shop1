# Coffee Shop

SPA-приложение интернет-магазина кофейного магазина, реализованное на Vue 2.  
Учебный проект курса Glo Academy по Vue.js.

Данные хранятся в mock-API (json-server), показывает индикатор
загрузки, открывает страницы товаров по ID, валидирует и сохраняет заявки
клиентов в базу данных.

## Реализованный функционал

- **Главная страница** — превью, блок "About Us" и карточки бестселлеров
- **Два каталога** — "Our Coffee" и "For Your Pleasure" с карточками товаров
- **Динамическая страница товара** — данные подтягиваются по ID из json-server
- **Переходы по карточкам** — клик по товару открывает его страницу (динамический роутинг)
- **Индикатор загрузки** — компонент Spinner показывается, пока данные едут с сервера
- **Форма обратной связи** — валидация через Vuelidate + чекбокс согласия с офертой
- **Сохранение заявок** — данные формы уходят POST-запросом и сохраняются в db.json
- **Vuex с модулями** — bestsellers, coffee, goods, links + общий isLoading
- **Переиспользуемые компоненты** — ProductCard, NavBar, BlockTitle, Spinner и др.

## Архитектурные принципы

- **Single Source of Truth** — все данные лежат в Vuex и json-server
- **Модульный Vuex** — каждый тип данных в своём модуле (`bestsellers`, `coffee`, `goods`, `links`)
- **Миксины для общей логики** — `navigate` (переходы по карточкам) и `loading` (управление isLoading)
- **Глобальное состояние загрузки** — `isLoading` в корневом store управляется через миксин, используется на всех страницах
- **DRY** — карточка товара `ProductCard` используется на всех страницах каталогов
- **Глобальные фильтры** — `addCurrency` для форматирования цены
- **Кастомные валидаторы** — собственный `minLength` в `src/validators/`

## Установка и запуск

### Требования
- Node.js (версия 12+)
- npm или yarn

### Шаги установки

1. **Клонировать репозиторий:**
   ```
      git clone https://github.com/Vladimir-cloudj/glo-academy-coffee-shop1.git
      cd glo-academy-coffee-shop1
   ```
2. **Установить зависимости:**
   ```
      npm install
   ```
3. **Запустить json-server (терминал №2):**
   ```
      json-server --watch db.json
   ```
4. **Запустить dev-сервер:**
   ```
      npm run serve
   ```
5. **Открыть в браузере:**
   ```
      http://localhost:8080/
   ```
**Важно:** оба сервера должны работать одновременно — приложение ходит за данными на порт 3000.

*Сборка для продакшена*
   ```
      npm run build
   ```

## Как это работает

Полный путь приложения — от открытия сайта до отправки формы:
1. Старт приложения. main.js создаёт инстанс Vue и подключает store, router, Vuelidate, глобальные стили и фильтры. В App.vue лежит <router-view/> — в нём рендерится страница текущего URL.
2. Главная страница (/, HeroView). В mounted() компонент вызывает startLoading() из миксина loading (это устанавливает глобальный флаг isLoading = true в корневом store).
Затем запрашивается GET /bestsellers. Пока ответ в пути — isLoading === true, и вместо карточек показывается компонент LoadingSpinner. Данные пришли → сохраняются в Vuex (action setBestsellers) → в .finally() вызывается endLoading() (устанавливает isLoading = false) → Spinner исчезает, рендерятся карточки бестселлеров.
3. Переход в каталоги. Кнопка "More" и пункты меню — это router-link'и.
На /our-coffee и /for-your-pleasure сценарий повторяется: mounted() → startLoading() → fetch (/coffee или /goods) → Spinner на время загрузки → dispatch в Vuex → endLoading() в .finally() → отрисовка карточек ProductCard.
4. Клик по карточке. ProductCard эмитит событие onNavigate(id). Миксин navigate принимает id и делает $router.push({ name, params: { id } }) — пользователь попадает на /our-coffee/:id или /for-your-pleasure/:id.
5. Страница товара (GoodsItemView). Компонент смотрит на имя роута (coffee или goods), чтобы понять категорию, вызывает startLoading() и запрашивает GET /coffee/:id или GET /goods/:id. На время загрузки — Spinner, после — баннер с названием, фото, страна, описание и цена. Если id не найден — блок "Товар не найден" с кнопкой на главную.
6. Форма обратной связи (ContactsUsView). При отправке Vuelidate проверяет поля ($v.$touch() + $v.$invalid): имя, e-mail, сообщение и чекбокс оферты. Если всё валидно — данные уходят POST /contacts, json-server записывает заявку в db.json. Затем форма очищается, а $v.$reset() сбрасывает состояние валидации.

## ️ Фильтры

В проекте используется глобальный фильтр `truncate` для форматирования текста:

```javascript
Vue.filter('truncate', (text, length = 400, suffix = '...') => {
  if (!text) return '';
  if (text.length <= length) return text;
  return text.substring(0, length) + suffix;
});
```

**Использование в компонентах:**
```vue
{{ tour.description | truncate(400) }}
```

**Преимущества:**
- Переиспользуемость во всех компонентах
- Настраиваемая длина обрезки
- Автоматическое добавление многоточия
